## K线功能介绍
K线（Candlestick）是行情分析中最基础、最核心的图表形态，用于展示某一交易对在特定时间周期内的价格波动轨迹。每根K线包含开盘、最高、最低、收盘四个价格维度以及成交量信息，能够直观反映市场的多空力量对比和趋势演变。K线图表是用户进行技术分析、识别形态、制定交易策略的主要工具。

#### K线前端显示
图表主体区域：横轴为时间，纵轴为价格，每个时间单位对应一根K线实体（阳线/阴线），同时可叠加多种技术指标（如MA、EMA、MACD、RSI等）。主图区域通常包含：
K线实体与影线：实体表示开盘到收盘的价差，影线表示最高/最低价范围。
价格坐标轴：左侧显示价格刻度，右侧可显示当前最新价。
成交量副图：在K线图下方独立显示成交量柱，与K线时间对齐。
十字光标：鼠标悬停时显示当前时间点的OHLCV数值及对应指标值。
委托线与仓位线：可在图表上叠加显示当前用户的限价委托单价格线，以及持仓均价线、止损/止盈线，便于用户直观对比市价与自身持仓/委托的关系。

#### K线交互
缩放与平移：支持鼠标滚轮缩放时间周期（如从1小时切换至15分钟），以及拖拽平移图表查看历史数据。
周期切换：提供快捷按钮（1m、5m、1h、4h、1d、1w等）切换K线粒度，切换时重新请求对应周期的数据并刷新图表。
指标管理：用户可添加/删除技术指标，调整指标参数（如MA周期），指标计算在客户端或服务端完成。
画线工具：提供趋势线、斐波那契、水平线等辅助画线功能，用于技术分析。
快捷交易：在图表上双击或右键可调出下单面板，支持快速平仓、修改委托单（如移动止损）、一键反向开仓等操作，将交易执行与图表分析紧密结合。
拖拽调整委托线/仓位线：用户可直接在图表上拖拽委托价格线或止损线，自动触发修改委托单或止损价格。

#### 数据模型
K线数据采用标准的OHLCV结构，每次推送或请求返回一个或多个K线对象。具体模型如下：
```typescript
/**
 * 单根K线数据
 */
interface Kline {
    // 核心价格数据（OHLCV）
    open: number;      // 开盘价
    high: number;      // 最高价
    low: number;       // 最低价
    close: number;     // 收盘价
    volume: number;    // 成交量（币/合约张数）
    
    // 时间标识
    openTime: number;      // K线开始时间（毫秒时间戳）
    closeTime: number;     // K线结束时间（毫秒时间戳）
    
    // 扩展字段（部分交易所提供）
    quoteVolume?: number;  // 成交额（USDT等计价货币）
    trades?: number;       // 成交笔数
    takerBuyVolume?: number; // 主动买入成交量
    takerBuyQuoteVolume?: number; // 主动买入成交额
}

/**
 * K线周期类型
 */
type KlineInterval = 
    | '1m' | '3m' | '5m' | '15m' | '30m'   // 分钟级
    | '1h' | '2h' | '4h' | '6h' | '8h' | '12h' // 小时级
    | '1d' | '3d' | '5d' | '7d'             // 日级
    | '1w' | '1M';                          // 周级、月级
```
#### 数据更新方式：
历史数据：初次加载时，通过REST接口请求指定周期和数量（如最近1000根）的K线数据。
实时增量：WebSocket订阅K线频道，当新的K线生成或当前未闭合K线发生变化时，推送增量数据（如最新一根K线的更新或新K线产生），客户端根据openTime识别并替换或追加。

#### k 线数据补全

补全的本质是用可得的最近有效信息填充缺失时间点，并遵循“无交易则无波动”的原则：
价格：沿用前一个有效K线的收盘价（或直接用该收盘价填充O、H、L、C四个价格，形成一字线）。
成交量：填充为 0（没有发生交易）。
时间索引：按所需的完整日历频率（如交易日历、自然日、分钟级序列）生成时间点，再填充缺失。
补全不是预测，不引入未来信息，只用过去已发生的数据。

#### 性能优化
K线图表面临的数据量远大于盘口（往往需要渲染数千根 K线及多种技术指标），且随着窗口缩放和指标切换，计算压力极大。优化策略如下：
增量渲染代替全量重绘
局部更新：新推送到来时，仅更新图表中最后一根未闭合 K线的实体/影线高度，或追加新生成的一根 K线，避免每次数据变更都遍历全部历史数据重绘 Canvas。
数据抽稀与视口裁剪（LOD 技术）
按需加载：图表库仅渲染当前视口（Visible Range）内的 K线，视口外的数据只保留内存模型，不参与绘制。
数据抽稀：当缩放等级较小（如显示全月数据）导致单个像素点容纳多根 K线时，采用 LTTB（Largest Triangle Three Buckets） 算法进行降采样，保留视觉趋势的同时大幅减少绘制指令（从上万根降至几百根）。
计算下沉至 Web Worker
指标隔离：将 MA、EMA、MACD、RSI、布林带等所有技术指标的计算逻辑迁移至 Web Worker 线程。
降频输出：Worker 完成计算后，不立即触发渲染，而是以 200ms~300ms 的固定频率将计算结果（仅包含指标数值）发送回主线程。主线程仅负责将数值映射为图形，极大释放主线程 UI 交互的阻塞压力。
缓存队列与更新防抖
批量去重：建立增量缓存队列，在极速行情（如逐笔推送）下，将 300ms 时间窗口内的所有 K线更新按 openTime 进行合并去重（同一根 K线只保留最新 close/high/low 数据），窗口到期后统一刷新图表。
限制队列容量：设置队列最大长度（如 200 条），超出时强制丢弃最旧数据或触发一次强制同步，防止内存溢出。
离屏缓存（OffscreenCanvas）
静态层分离：将背景网格、价格坐标轴、历史已定型的 K线（已闭合）绘制在离屏 Canvas 上作为静态图层。主 Canvas 仅负责重绘最新 K线和十字光标等动态元素，利用 drawImage 合成，减少重绘区域的像素处理量。
内存回收策略
滚动窗口：仅保留最近 2000~5000 根 K线数据，超出部分自动从内存数组中剔除（或存入 IndexedDB 做持久化缓存），避免因长期运行导致浏览器 Tab 崩溃。切换周期（如从 1m 切到 1h）时，立即释放旧周期数据，申请新周期数据。
