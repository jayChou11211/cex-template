## 概述
订单簿（Order Book）是数字资产交易系统的核心组件，集中展示所有未成交的买卖委托信息，是交易撮合、
市场深度展示和价格发现的基础设施。订单簿由买方挂单（Bid）和卖方挂单（Ask）两侧构成，每个挂单包含价格和数量两个核心要素。
现代交易所普遍采用 “全量快照 + 增量更新” 的数据推送模式：连接建立或重连时下发完整订单簿快照，之后持续推送增量更新

## OrderBook 功能介绍

价格发现：订单簿直观展示市场认可的买卖价格区间，交易者可对最优买价（Best Bid）、最优卖价（Best Ask）一目了然。
市场深度：通过订单簿可观察不同价格区间的买卖力量强弱，预估市场支撑位和阻力位。


#### 数据模型
典型的 L2 订单簿（Market-by-Price，按价格聚合）结构如下
每次推送相同的价格数量替换，数量为0，直接移除。

[orderbook.ts](./orderbook.ts)

```ts
interface OrderBook {
    bids:  Arrary<OrderLevel>,  // 买单：价格从高到低
    asks:  Arrary<OrderLevel>,  // 卖单：价格从低到高
    last_seq: Number,                         // 当前序列号，用于检测丢包
}

interface OrderLevel {
    price: Number,      // 价格（生产环境建议用整数表示）
    volume: Number,     // 累计委托量
}
```

#### 数据补偿机制

- 前端来做
    序列号校验：每条增量消息都带有一个单调递增的序列号（Sequence Number）。客户端每应用一条消息，都会记录当前的序列号 lastSeq。收到新消息时，会校验其序列号 seq 是否等于 lastSeq + 1。
    触发补偿：如果 seq > lastSeq + 1，说明中间有数据丢失，本地订单簿已“中毒”，需要立即触发补偿流程。
    补偿流程：立马请求快照，在快照返回期间推送数据保存在 队列里，快照返回后，拿快照 seq+1去取缓存的 推送 重新 update
    [orderbook数据补偿.ts](./orderbook数据补偿.ts)

- 后端来做
  后端每次发现有跳号就推一次全量数据，
  ws 每次连接先推全量数据

#### 合并深度
可以选择 0.01 0.1 1 10 合并，
卖盘价格区间内向上合并
买盘价格区间内向下合并
